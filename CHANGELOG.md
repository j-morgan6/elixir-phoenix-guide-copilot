## [2.6.0] - 2026-10-15

Synced with elixir-phoenix-guide 2.6.0.

### Added
- Five new instructions: `phoenix-scopes-and-generators`, `phoenix-tailwind-daisyui`, `ecto-migrations-safety`, `ecto-queries-performance` and `http-clients-req` (24 in total). `AGENTS.md` gains Ecto Migrations, Ecto Queries and HTTP Clients reference sections.
- GitHub Actions CI: the hook suite runs against `elixir-hook.sh` on Ubuntu and macOS (`/bin/bash` 3.2) and against `elixir-hook.ps1` with PowerShell 7 on Linux and Windows and with Windows PowerShell 5.1 on Windows; shellcheck on all shell scripts.
- `.gitattributes` keeps LF line endings so the bash hook works from Windows checkouts.

### Changed
- **Narrower `applyTo` patterns.** Most instructions targeted every `.ex` file, so a LiveView loaded 17 of 19 instructions and a context 14. Patterns now follow Phoenix's layout (contexts and schemas, `live/`, `controllers/`, migrations, `channels/`, workers, `config/`…): a LiveView or context loads about 6. `code-quality` now loads only for `.credo.exs` (ask for it when refactoring).
- The README's instruction count, `applyTo` table and file tree are generated by the upstream sync script, so they always match the instruction files.

### Fixed
- Test harness converts paths to `C:/…` form under Git Bash, so the PowerShell suite runs on Windows.

## [2.5.0] - 2026-10-15

Synced with elixir-phoenix-guide 2.5.0: every instruction re-verified against Elixir 1.20, Phoenix 1.8.15, LiveView 1.2.12, Ecto 3.14 and Oban 2.24 (scoped context calls, security fixes, Phoenix 1.8 `phx.gen.auth` accuracy, forms and async in LiveView). See the upstream CHANGELOG for the content changes.

### Fixed
- **Advisories now reach Copilot.** `preToolUse` only honours `permissionDecision`/`permissionDecisionReason`/`modifiedArgs`, so advisories emitted there were dropped. `pre edit` now only blocks; review notes come from `post edit` as `additionalContext`.
- **Hooks fail open.** A crashing `preToolUse` hook denies the tool call; both scripts now exit 0 on bad input, a missing `jq` or an internal error (`elixir-hook.ps1` previously ran with `$ErrorActionPreference = "Stop"` and no catch).
- **`elixir-hook.ps1` deny paths** emit `permissionDecision` JSON (via `ConvertTo-Json -Compress`) instead of `Write-Error`, and the script is now behaviourally identical to `elixir-hook.sh` (closes the 2.4.0 known gap).
- Command guard splits commands into segments and ignores quoted text, comments and heredocs: `MIX_ENV=test mix ecto.reset` and commit messages mentioning it are allowed; `mix ecto.drop`, `+refspec`, `-uf` and `git -C dir push --force` are blocked; it only runs in Elixir projects.
- Open-redirect check matches `redirect(external: params…)` instead of the safe `to:` form.
- SQL interpolation in `Repo.query`/`SQL.query` (including heredocs) is caught directly.
- Comments, `@doc`/`@moduledoc` text and HEEx comments are ignored; `deps/`, `_build/`, `node_modules/` and `.elixir_ls/` are skipped.
- `form_for` has a word boundary; Logger is only flagged when it interpolates a sensitive name; `IO.inspect`/`dbg` are allowed in `mix/tasks/`; `@impl` is only required on a callback's first clause; migration index checks are per table.

### Added
- `EPG_ALLOW=force_push,ecto_reset,ecto_drop` opt-out (command prefix, earlier `export` in the same command line, or the hook environment).
- `push_redirect` flagged as deprecated.
- Hooks accept `toolArgs` as an object or JSON string, Copilot `edit`/`create` arguments, VS Code-style `filePath`/`newString`, and MultiEdit-style `edits[]`.
- `tests/run_tests.sh [sh|ps1]` hook test suite (190 bash / 189 PowerShell cases).
- `AGENTS.md` is regenerated from the upstream skills' reference files: Ecto Reference, Phoenix Project Structure, LiveView Checklist, LiveView JS Interop, Testing Reference.
- `scripts/lib/common.sh` (shared helpers for `detect_project.sh` and `run_analysis.sh`).

### Changed
- Block-tier checks (SQL/fragment interpolation, external redirect from params, `form_for`, `live_redirect`/`live_patch`/`push_redirect`) deny before the write; review-tier checks arrive after the write.
- Only the code being written is judged (with whole-file context), so existing code is never re-flagged.
- `@current_user` is a review note, and only when the project actually uses scopes.
- `scripts/code_quality.exs`: unused-function detector removed (use `mix compile --warnings-as-errors` and `mix xref`), "ABC" renamed to branch complexity, duplication compared across the whole tree.

### Removed
- Checks that were wrong or noisy: `MIX_ENV=prod` block (blocked release builds), `<.flash_group` block (the 1.8 generator uses it), `static_paths` mismatch, hard-coded upload path and file-size blocks, nested if/else, Enum chains, string concatenation in Enum, `auto_upload` without progress, `IO.puts`, missing-preload guess, `with` without `else`, column-removal and NOT NULL migration warnings.
- The per-write "did you invoke the skill" reminder and the per-write `code_quality.exs` run (its output was discarded).

### Known gaps
- `elixir-hook.ps1` is tested with PowerShell 7 on macOS, not Windows PowerShell 5.1.
- `scripts/detect_project.sh` (run manually) writes its cache under `~/.claude/elixir-phoenix-guide/` unless `CLAUDE_PLUGIN_DATA` is set; the hooks don't use it.

## [2.4.0] - 2026-07-03

### Fixed
- **Advisory hook output** — `elixir-hook.sh` and `elixir-hook.ps1` previously wrote advisory/warning messages to stderr, which Copilot's hook runner discards entirely on exit 0. All advisories are now emitted as `{"additionalContext": "..."}` JSON on stdout via a new `emit_context` (bash) / `Emit-Context` (PowerShell) helper, matching Copilot's hook-output contract. Deny paths (`{"permissionDecision":"deny",...}`) were already correct and are unchanged.
- **Post-write check ordering** — in both hook scripts, the generic "did you invoke the skill" reminder previously ran first and (since only one JSON object can be emitted per invocation) silently prevented every other post-write advisory — mix.exs audit reminder, missing-preload warning, `with` missing-else warning, and LiveView/Repo boundary-violation warning — from ever being seen. Reordered so specific, actionable warnings run first and the generic reminder is a fallback.
- **`code_quality.exs` stdout leak** — its plain-text analysis output was being interleaved with the hook's own JSON on stdout, corrupting the JSON contract; stdout is now suppressed for that invocation.
- Header comments in both hook scripts corrected: hooks are configured in `elixir-guard.json`, not `hooks.json`.
- **`security-essentials.instructions.md`** — `applyTo` now includes `**/*.html.heex` (previously `.ex`/`.exs` only), so security guidance also loads for HEEx templates.

### Changed
- All 19 instruction files resynced from the corrected canonical skills in `elixir-phoenix-guide` (skills were substantially revised there since this port was first generated; this is the first resync). `deployment-gotchas`, `elixir-essentials`, `phoenix-liveview-essentials`, `ecto-nested-associations`, and `phoenix-liveview-auth` changed the most.
- `scripts/code_quality.exs`, `scripts/detect_project.sh`, and `scripts/run_analysis.sh` recopied from canonical sources.
- Added `scripts/sync_copilot.sh` upstream (in the `elixir-phoenix-guide` repo) to regenerate this port mechanically going forward.

### Removed
- **`detect_template_duplication.sh`** and all references to it (hook call sites, `run_analysis.sh`, `README.md`) — removed upstream from `elixir-phoenix-guide` and no longer shipped here.

### Known gaps
- `elixir-hook.ps1`'s deny paths still use `Write-Error` + `exit 2` instead of a `{"permissionDecision":"deny",...}` JSON object on stdout (unlike `elixir-hook.sh`, whose deny paths are already correct). Reworking every PowerShell deny site is a larger follow-up.
